# CLAUDE.md — wishlist-platform

Ты работаешь над «комнатой»: личная страница человека — фотореальный интерьер,
где объекты — зоны его мира (полки → книги, гардероб → одежда, проигрыватель →
музыка). **Состояний у вещи нет** (решение владельца 09.08.2026, тикет 124:
«всё, что хочет хозяин, и есть его любовь»). Различие живёт в МЕСТЕ:
**комната — чего хочется** (бронируется, цена по `priceVisibility`, степень
желания `desire`), **сокровищница — что уже моё** (не бронируется, цены гостю
не видно). Гости **тихо** бронируют подарки; после праздника хозяйка отмечает
«Дошло» — вещь уезжает в сокровищницу, имя дарителя раскрывается, появляется
связь. Место обратимо («Вернуть в комнату»), раскрытие имени — нет.

**Источники правды:**
- продукт — `docs/PRD.md`; архитектура — `docs/ARCHITECTURE.md`; порядок — `docs/ROADMAP.md`;
- UI и поведение — **дизайн-пакет `design/package/`**: `handoff/items.json`
  (модель вещи), `rooms.json` (130 зон в контракте, 120 в рендере — зона без
  записи в `zones.json` не показывается, ADR-0003), `zones.json`, `tokens.json`,
  `motion.json`, макет `Main Screen.dc.html`. Код воплощает эти значения, а не
  изобретает свои. Расхождение с пакетом без согласования = баг.

## Стек (зафиксирован)

- **Next.js 16+ (App Router, RSC) + React 19 + TypeScript strict**
- **Tailwind CSS v4** — токены генерируются из `handoff/tokens.json`; **Motion**
- Шрифты: Archivo (display) / Onest (UI) / Instrument Sans — через next/font
- **PostgreSQL 17 + Prisma** (+ pgvector) · **Redis + BullMQ**
- **Auth.js** — вход без пароля (magic link); второй способ Apple/Google/
  Telegram — один раз, перед первым шером. СМС нет.
- **Zod** · **S3/MinIO + CDN** · **Playwright** (e2e + fallback-парсер) ·
  **next-intl** (ru + каркас en) · Sentry + OTel + PostHog (prod)
- **three.js — НЕ тащить вообще** (ADR-0001): оживление вещей — CSS-покачивание
  (в проде) и 2.5D-параллакс по карте глубины (Phase 2). Платная генерация
  3D-моделей отвергнута владельцем; пересмотр — только явным решением.

Крупные зависимости не добавлять без явного согласования.

## Команды

```bash
docker compose up -d          # postgres + redis + minio
npm run dev                   # Next.js dev server
npx prisma migrate dev        # миграции
npx prisma studio             # просмотр БД
npm run worker                # BullMQ worker (отдельный процесс)
npm run tokens                # Tailwind-токены из handoff/tokens.json
npm run lint && npm run typecheck
npm run test                  # vitest (unit)
npm run test:e2e              # playwright: сам поднимает dev-сервер на :3100
                              # в СВОЁМ каталоге сборки .next/e2e (тикет 155)
```

Поддерживай команды рабочими; меняется структура — обнови этот файл.

**У e2e свой каталог сборки, потому что блокировка Next по КАТАЛОГУ, а не по
порту.** Next 16 держит `<distDir>/dev/lock` и не пускает второй `next dev` в тот
же каталог — своего порта :3100 мало, рядом с живым `npm run dev` прогон падал
до первого теста. Поэтому `next.config.ts` читает `distDir` из `NEXT_DIST_DIR`, а
`playwright.config.ts` задаёт его сам (`.next/e2e`) в `webServer.env`: руками
помнить нечего. Отсюда же следствие — **`next-env.d.ts` не под гитом** (Next
переписывает его под текущий каталог при каждом старте; так велит и он сам), а в
`tsconfig.json` пути обоих каталогов лежат рядом и не мигают.

## Конвенции

- Серверные компоненты по умолчанию; `"use client"` — только интерактив.
- **Координаты зон — только из `rooms.json`**, в системе **кадра 630×351**
  (ADR-0006). Из неё выводятся обе раскладки: десктоп `x × 1.7778` (кадр виден
  целиком), телефон `x − 12` (окно 430 ездит по кадру и показывает его с 12 по
  442). Слагаемого `+12` в проекции больше нет — оно переводило прежнюю
  разметку из координат окна. 33 зоны в покое за правым краем окна: это не
  ошибка, дорога к ним — указатель зон.
  Наезд камеры считается формулой из `motion.json`, руками не задаётся.
  Отдельной десктопной карты координат не существует и не должно появиться.
- **Изображения комнат (`design/package/refs/`) неприкосновенны**: не
  перегенерировать, не кадрировать; retina — апскейл существующего файла.
- Анимации — по `motion.json` (кривая, длительности, стаггер);
  `prefers-reduced-motion` по контракту; hover — за воротами
  `(hover:hover) and (pointer:fine)`; любой нажимаемый элемент проседает
  scale(.97) 160ms.
- Кнопки: «полоса света» — главная везде; «бирка» — ровно одно действие
  «подарить» в режиме гостя, больше нигде (турн 22).
- API: route handlers `app/api/v1/...`, ответы `{ data } | { error: { code, message } }`.
- Бизнес-логика в `src/server/services/*`; роуты тонкие; DTO-слой
  `src/server/dto/*` — единственное место сериализации.
- Деньги: `Decimal`, никогда float; валюта ISO 4217 отдельным полем.
- Парсер — изолированный модуль `src/server/parser/` с адаптерами (+фикстуры).
- Каталог и AI — за флагами `CATALOG_ENABLED` / `RECOGNIZE_ENABLED`.
- Тесты обязательны: парсер (фикстуры), сервис брони, DTO-инварианты, переезды
  вещи (`receiveGift` и `toggleHall`); e2e на happy path фазы.
- Коммиты conventional (`feat:` …), атомарные. Секреты только через env.

## Критичные инварианты (никогда не нарушать)

1. **Тихая бронь — без исключений.** Хозяйке — только счётчик «N вещей уже
   забраны» по комнате. Ни имени, ни вещи, ни в API, ни в кэше. Складчина
   тиха при любом числе участников (в счётчике — одна вещь); прогресс сбора —
   только гостям. Счётчик может убывать (отмена/несбор) — не скрывать.
   `itemForOwner` не содержит booking — покрыто тестом.
2. **Необратимо только РАСКРЫТИЕ ИМЕНИ дарителя** — ровно один раз, на экране
   «что подарили» (`OccasionSummary.revealedAt`), и пишет его единственная
   функция `receiveGift`. **МЕСТО ВЕЩИ ОБРАТИМО**: «Вернуть в комнату» есть и
   работает, возврат имени не отменяет и второй раз не запускает (тикет 124,
   решение владельца 09.08). Имена и место вещи — две разные вещи, связывать
   их нельзя. Тест обязателен.
3. ~~Пунктир кодирует «хочу»~~ — **ОТМЕНЁН ЦЕЛИКОМ** (тикет 124). Состояния
   ушли, кодировать пунктиром нечего: плитка у всех с обычной границей,
   вещь без фото — серая заливка со значком пула. Тест держит обратное:
   пунктира не бывает ни при каком входе. Номер не переиспользовать — пусть
   у отменённого правила останется его место.
4. **Друзья не добавляются.** В API нет и не будет поиска людей и импорта
   контактов. Связь — из подарка или открытой ссылки.
5. Спрятанные вещи и выключенные зоны не отдаются гостям (фильтр на чтении,
   тест). Выключенная зона исчезает с мебелью.
6. **SSRF-защита**: любой чужой URL — только через `safeFetch`
   (ARCHITECTURE §11). Чужие изображения не хотлинкуем — в своё S3.
7. Комната гостя доступна по shareSlug и не попадает в sitemap (индексация —
   открытый вопрос, дефолт закрытый).
8. **Цена вещи КОМНАТЫ — по `priceVisibility`; цена в СОКРОВИЩНИЦЕ гостю не
   показывается вовсе** (тикет 124, модель v2 дизайна). Хозяйке её
   собственные цены видны всегда, включая её собственную витрину. Переезд
   цену не стирает — он её перестаёт показывать: «Вернуть в комнату»
   показывает снова. **Скрытая цена скрывает ЧИСЛО, а не путь к вещи**:
   ссылка «Где купить» показывается всегда, когда она есть, при любом
   `priceVisibility` (тикет 195, решение владельца 11.08.2026). Агрегаты (диапазон цен, марки в сводке зоны) считаются
   по вещам КОМНАТЫ с открытой ценой и не показываются, если таких вещей
   меньше трёх или различных марок меньше трёх; **вещь витрины в агрегат не
   входит никогда**. Счётчики зоны: гостю ОДНОЙ строкой «N из M свободны»
   (а не два числа рядом — правило пакета `zoneCounterGuest`; крайние случаи
   своими словами: «все 4 свободны», «все 4 уже дарят»). Второе число считает
   ЭКРАН по некэшируемому каналу «занято» — в кэшируемой сводке его нет и
   быть не может: хозяйка открывает свою же ссылку и получила бы тот же
   кэшированный HTML. Хозяйке — только «N вещей».
9. **Зона `money` показывается — внутри копилка на мечту, без переводов.**
   Хозяйка называет цель, гость говорит «я участвую», деньги идут МИМО
   сервиса: он их не принимает, не хранит и не переводит (PRD §12а не
   менялся). Копилка ведёт себя как складчина: хозяйке — только общий счётчик
   «N вещей уже забраны», где копилка считается **одной** вещью при любом
   числе участников; прогресс сбора, суммы и участников видят только гости
   (ADR-0008, отменил решение 2 из ADR-0004).

   **У ПОЛКИ ТРИ СОСТОЯНИЯ, И 404 — ТОЛЬКО У ОДНОГО** (тикет 235, решение
   владельца 14.08.2026 по пакету 50). «Предмета нет в интерьере» больше не
   значит «зоны нет»: это **живая полка без места на кадре**
   (`zonesWithoutRect` в `src/config/design.ts`) — страница отвечает 200, вещи
   на месте, добавление работает, вход через список зон комнаты
   (`/room/list`); нет ровно двух вещей — метки в кадре и наезда камеры, потому
   что метка живёт на прямоугольнике, а ехать некуда. Ради этого всё и
   затевалось: человек меняет интерьер и не теряет полку вместе с вещами
   («переезд без потерь», приёмка 14.08, замечание 7) — тест обязателен.
   **404 остаётся за выключенной хозяйкой** (`Room.zonesOff`, инвариант №5) и
   за рабочей дверью «спрятать зону адресно» (`zonesHiddenByProduct`) — **дверь
   сегодня ПУСТА**: тикет 234 разметил последние адреса, и 404 по продуктовому
   решению больше нет нигде. Дверь оставлена рабочей: следующее такое решение
   владельца пишется одной строкой.

   Сколько чего — **считается, а не помнится**, и числа держит тест
   `design-contract`: адресов в карте **134** (13 в женских комнатах, 14 в
   мужских — полка «Бар и табак» решением владельца 14.08), меток в кадре
   **126**, живут списком **8**. Прежнее «122 зоны из 130» умерло вместе с
   прежним значением флага `objectAbsent`; меток в кадре меньше, чем полок, и
   это норма, а не недостача.

## Порядок работы

- Строго по фазам `docs/ROADMAP.md`; фаза закрыта по DoD (тесты + доки).

- Смотри соответствующий турн макета перед вёрсткой экрана (номера — в
  `handoff/README.md`); чего в макете нет — список 19b, приоритеты P0/P1/P2.
- Открытые вопросы (PRD §12) не решай молча — варианты пользователю, в коде
  нейтральный дефолт за флагом.
- Пользователь — продакт с банковским бэкграундом, не full-time разработчик:
  объясняй решения кратко, по-русски, без жаргона.
