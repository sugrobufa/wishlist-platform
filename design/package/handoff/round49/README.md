## Главное из пяти: ключа не было потому, что кнопки не должно быть

Ваш grep нашёл больше, чем искал. `occasion.json` **противоречил сам себе**:
таблица `buttonLife` говорит «OPEN — ни кнопки, ни ссылки», а `states.OPEN.loud`
строкой выше называет громкую кнопку. Я перенёс её из турна 21a не думая — там
она была залитой кнопкой ещё до правила о полосе света.

Проверять надо было не слово, а саму кнопку: **«спасибо всем» продукт отправить
не может**. Почта гостя необязательна (`Booking.emailLabel`), значит на любом
составе, где хоть у одного её нет, кнопка «всем» врёт — а ваше же правило
раунда 3 запрещает сообщать человеку о том, чего у нас нет.

Новый ключ один: **`Occasion.thanksGuest`** = «Сказать спасибо», тихой ступенью
**в строке подарка**, цель 44, только когда у гостя есть почта. Нет почты — нет
строки (не серой, не выключенной — никакой).

## Что эта ошибка стоила раскладке

Числа 5/4 держали строку «цена · огоньки · слово» из турна 54c. **Настоящая
точка с целью 44 в мета-строку не встаёт** — шкала переезжает своей строкой, как
в форме. Раскладка 54c отменяется: она была следствием ошибки в числах, а не
решением.

И ответ на ваш вопрос «что делает тап, если цель одна на всю полосу»: **цель не
одна**. `hitTarget` «полоса целиком» снимаю — у каждого огонька своя цель 44×44.
Тап по уже стоящей ступени снимает степень, шкала возвращается в «не сказано»;
диалога нет, потому что действие обратимо тем же тапом.

## Ваша находка про строчную букву касалась трёх мест

Проверил весь файл. Строчных разделов было три:

- `pool` → **`PoolInline`** — другое место, чем `Pool`: строка складчины в
  списке вещей, а не экран координации. Внутри — 4 блока живых строк;
- `zoneCounterGuest` → **`ZoneCounterGuest`** — шесть живых строк счётчика,
  тоже шли мимо сторожа;
- `phoneFieldRemoved` → **`_phoneFieldRemoved`** — живых строк нет, это запись
  решения. Подчёркивание вместо строчной буквы: «не словарь» должно читаться
  намеренно.

Цена — find-replace двух имён у вас в коде.
