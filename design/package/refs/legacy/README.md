# legacy — кадры «открыто» прежних раундов, отключены

29 файлов, которые до раунда 4 были кадрами раскрытия зон (`openFrame` в
`handoff/rooms.json` раунда 2). Продукт их больше не показывает, и раздача их
не видит: маршрут `src/app/rooms/[image]/route.ts` принимает только плоские
имена без слэшей, файл из подпапки по URL не достать.

## Почему отключены

Приёмка раунда 3 ввела числовой порог для кадра «открыто»:

| Величина | Что значит | Порог |
|---|---|---|
| **своя** | расхождение с базовым кадром внутри своего прямоугольника | ≥ 0.05 |
| **отн** | своя ÷ среднее расхождение по чужим зонам | ≥ 3.0 |

Смысл второго числа: продукт делает кроссфейд между базовым кадром и «открыто».
Если вместе с предметом меняется фон, при открытии зоны у человека дёргается вся
комната — контракт это прямо запрещает («любое смещение камеры или света
читается как рывок»).

**Из этих тридцати кадров порог не прошёл ни один.** Замер по всем (тикет 33):
«отн» от 0.53 до 1.82 при пороге 3 — то есть фон меняется не слабее предмета,
а у половины кадров сильнее. Это не брак съёмки, а прежний метод: кадр
генерировался заново целиком, а не правкой одного предмета в существующем.

## Почему не удалены

Репозиторий не под git — удаление было бы безвозвратным. Здесь они не мешают
и остаются доказательством замера.

## Почему их нельзя было оставить рядом

Имена совпадают со схемой нового контракта (`o-<комната>-<зона>.jpg`). Половина
из них заняла бы имена, которые контракт отдаст новым кадрам после пересъёмки, —
и продукт молча показал бы старый кадр вместо нового. Тест
`tests/design-contract.test.ts` («на именах непринятых зон в refs не лежит
ничего») сторожит это место.

Исключение — `o-study-fashion.jpg`: эта зона порог прошла, и файл с тем же
именем уже заменён новым кадром. В этой папке его нет.
