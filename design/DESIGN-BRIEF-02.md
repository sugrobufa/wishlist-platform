# Бриф для дизайн-сессии №2 — после первой приёмки продукта

Дата: 2026-08-05 · Автор: владелец продукта + инженерная сторона
Предыдущий пакет (действующий источник правды): `handoff/` — items.json,
rooms.json, zones.json, tokens.json, motion.json + 41 изображение.

## Как пользоваться этим файлом

Перетащи в чат дизайн-сессии **вместе с**:
1. `messages-ru-current.json` — все тексты продукта сегодня (правим их же);
2. скриншотами из приёмки (главный экран комнаты и метки зон) — они у владельца.

---

## 0. Что уже построено (контекст)

MVP собран и работает целиком: онбординг → комната-сцена с наездом камеры →
вещи «люблю/хочу» (руками и по ссылке из магазина) → публичная комната по
ссылке → тихая бронь гостем → счётчик у хозяйки → «что подарили» → зал славы →
связи → письма → настройки → GDPR. 400 автотестов зелёные, скорость в норме
(Lighthouse 90 mobile).

Дизайн воплощён буквально по пакету: координаты зон, партитура движения,
токены, кадры — всё из handoff-файлов, ничего не выдумано кодом.

**Первая живая приёмка выявила четыре дизайнерские проблемы.** Они ниже.
Три остальных пункта приёмки — инженерные, дизайна не касаются.

## 1. ГРАНИЦЫ: что нельзя сломать (и почему)

Прочитай до задач — это дешевле, чем переделывать.

### 1.1 Одна карта координат на всё

Зоны заданы прямоугольниками `x, y, w, h` в **телефонной системе 430×352**;
кадр комнаты внутри неё — 630×351 со сдвигом x = −12. Десктоп получается
умножением на 1.7778. **Отдельной десктопной карты не существует.**
Наезд камеры вычисляется формулой из центра прямоугольника — не рисуется.

### 1.2 Кадры и хотспоты — одно целое

84 прямоугольника зон привязаны к композиции конкретных кадров (10 комнат) +
30 кадров «открыто». **Новая генерация тех же комнат по тому же промпту даёт
другую расстановку мебели — и все 84 хотспота едут.** Поэтому:

- изменение кадров **без** изменения геометрии (апскейл, шумодав, цветокор,
  ретушь без сдвига предметов) — безопасно, координаты остаются;
- изменение композиции (новая генерация, кроп, другой ракурс) — требует
  **полной переразметки rooms.json** и пересъёмки соответствующих кадров
  «открыто». Это не запрещено, но должно прийти пакетом: кадры + новый
  rooms.json + кадры «открыто», иначе продукт развалится.

### 1.3 Контракты правим значениями, не структурой

Код читает handoff-файлы по именам ключей. Меняй **значения** сколько нужно;
переименование/удаление ключей = поломка кода. То же для текстов: в
`messages-ru-current.json` **ключи неприкосновенны, правим только строки**.

### 1.4 Бюджет

Первый экран сцены ≤ 2 МБ после сжатия (сейчас 193 КБ — запас огромный).
60 fps. `prefers-reduced-motion` обязателен. Цель нажатия ≥ 44 px.
three.js в проект не входит (решение владельца, ADR-0001): оживление вещей —
CSS и 2.5D-параллакс по карте глубины.

## 2. ЗАДАЧА A (приёмка п.2) — качество кадра и «вау» главного экрана

**Владелец:** «Качество снимка основной комнаты сильно просело, надо сделать
намного выше, нужен вау-эффект. Возможно, даже не нужны управляющие кнопки
такие крупные, как сейчас, — просто почти на весь экран».

### Что мы измерили

| Факт | Значение |
|---|---|
| Физический размер кадра | **1200 × 670 px**, JPEG, ~120 КБ |
| Показ на десктопе | до **1120 CSS-px** по ширине |
| На retina-экране (2×) требуется | **2240 px** — есть 1200 |

То есть картинка на обычном ноутбуке растягивается почти вдвое сверх своего
разрешения. Это и есть «просело качество» — не цветокор, а физический размер.

### Что решить и вернуть

1. **Разрешение кадров.** Нужны версии ≥ 2400 px по ширине (лучше 3000 для
   запаса на большие экраны), формат исходника — PNG/JPEG высокого качества,
   производные (AVIF/WebP) сделаем сами.
   - **Безопасный путь:** апскейл существующих кадров (нейросетевое увеличение
     + деликатная ретушь), геометрия совпадает до пикселя → координаты зон
     не трогаем вовсе. Предпочтителен, если качество апскейла устраивает глаз.
   - **Дорогой путь:** новые кадры в высоком разрешении. Тогда обязательно:
     обновлённый `rooms.json` со всеми координатами + все кадры «открыто» той
     же комнаты. Можно сделать так для 1–2 флагманских комнат, остальные —
     апскейлом.
2. **Композиция экрана.** Сцена почти во весь экран: предложи раскладку для
   телефона и десктопа — где живут имя комнаты, счётчик, кнопки, ссылки
   («Добавить вещь», «Зал славы», «Связи», «Настройки»), чтобы они не спорили
   с картинкой. Сейчас «Добавить вещь» — крупная кнопка над сценой, владельцу
   мешает. Варианты: собрать в тихую панель по краю, спрятать за одну иконку,
   показывать по наведению/скроллу — на твоё усмотрение, критерий один:
   **первым делом человек видит комнату, а не интерфейс**.
3. При каком соотношении сторон сцена смотрится лучше всего? Сейчас 430:352
   (почти 1.22:1) — если для «во весь экран» нужен другой кроп, скажи прямо,
   мы обсудим цену (это меняет карту координат).

## 3. ЗАДАЧА B (приёмка п.3) — метки зон

**Владелец:** «Не нравится, как помечены зоны для подарков — просто квадратики».

### Как сделано сейчас

Каждая зона — прямоугольник поверх фото: тонкий белый контур (1 px,
rgba 255/249/242), мягко пульсирует (цикл 4.5 с, сдвиг между зонами 900 мс),
при наведении добавляется свечение (внутренняя обводка + внешний ореол).
Прямоугольники честно повторяют координаты из rooms.json — отсюда «квадратики».

### Что решить и вернуть

Новый визуальный язык «здесь можно подойти». Идеи для отталкивания (не
ограничение): свет **по силуэту предмета**, а не по рамке; тёплое свечение,
как будто предмет подсвечен изнутри; едва заметная пылинка/блик; появление
метки только при приближении курсора; «дыхание» света вместо контура.

**Важно про цену решений:**
- если метка — эффект **внутри прямоугольника** (свет, градиент, виньетка,
  частицы) — это бесплатно, работает сразу на всех 84 зонах;
- если метка **повторяет силуэт предмета** — понадобится маска-картинка на
  каждую зону (84 файла) или SVG-контуры. Это возможно, но должно быть
  осознанным решением: скажи объём и приложи образец на 2–3 зонах.

Верни: описание состояний (покой / наведение / фокус с клавиатуры / нажатие),
значения (цвета, размытия, длительности) в формате, пригодном для добавления
в `tokens.json`, и обязательно — как это ведёт себя **на светлой комнате**
(кремовая) и **на тёмной** (неоновая): белое свечение на светлом фоне пропадает.

## 4. ЗАДАЧА C (приёмка п.6) — «походка» камеры вместо рывка

**Владелец:** «Не нравятся рывки к зонам, речь шла о плавном переходе камеры и
как бы имитация движения человека к предмету».

### Как сделано сейчас (партитура motion.json, воплощена буквально)

| Что | Значение |
|---|---|
| Камера идёт к зоне | 560 мс (телефон) / 620 мс (десктоп), кривая `cubic-bezier(.23,1,.32,1)` |
| Масштаб | ×1.72 телефон / ×1.45 десктоп, одним движением |
| Периферия темнеет | 400 мс |
| Мебель «открывается» (кроссфейд) | старт на 420/440 мс, длительность 400 мс |
| Вещи встают в сетку | старт 620/660 мс, шаг 60 мс на плитку |
| Выход | сетка гаснет 220 мс → камера отъезжает 560/620 мс |

Одно движение с резким стартом — отсюда ощущение рывка.

### Что решить и вернуть

Партитуру «подхода человека»: разгон из покоя, основное движение, мягкое
торможение у цели (возможно, микро-перелёт и оседание), лёгкая «дыхательная»
неровность вместо машинной прямой. Опиши **фазами**: время, что происходит,
кривая. Если нужна пружина — дай параметры (жёсткость/затухание или
duration+bounce), мы умеем.

Отдельно: должен ли меняться сам масштаб приближения (сейчас ×1.72/×1.45), и
как ведёт себя выход — «быстро внутрь, спокойно наружу» или наоборот.
И что делать при `prefers-reduced-motion` (сейчас: анимации выключены,
переходы 120 мс).

Формат ответа — обновлённый блок `openZone`/`closeZone` в motion.json
(структуру ключей сохрани, значения меняй свободно; новые фазы — добавляй
элементами массива с теми же полями).

## 5. ЗАДАЧА D (приёмка п.5) — тексты

**Владелец:** «Сделай проверку всех текстов, они сейчас айтишниковские, а не
пользовательские».

Все строки продукта — в приложенном `messages-ru-current.json` (≈320 строк,
сгруппированы по экранам: Home, SignIn, Onboarding, Room, Scene, ZoneGrid,
AddItem, Booking, MyBookings, GuestRoom, Occasion, Hall, Connections, Settings,
DataSection).

### Примеры того, что режет глаз

- «наезд есть, кадра „открыто" ещё нет» — служебная фраза из технического
  контракта, попала прямо в интерфейс;
- «набор зон», «Все 10» — наш внутренний язык, не пользовательский;
- «Комната по ссылке», «зона целиком списком» — то же.

### Что вернуть

Тот же файл с переписанными значениями (**ключи не менять — код ищет строки
по ним**), плюс короткая памятка тона: как мы называем вещи в интерфейсе
(комната, зона, вещь, «люблю»/«хочу», бронь…), чего избегаем, как звучим в
пустых состояниях и ошибках. Тон продукта — тихий, тёплый, без восклицаний и
маркетинга; человек должен чувствовать себя дома, а не в сервисе.

Английские строки есть, но их правку можно отложить — рынок русский.

## 6. Что именно вернуть в проект (чек-лист)

| Задача | Артефакт |
|---|---|
| A — качество | Кадры комнат в высоком разрешении (≥2400 px). Если композиция менялась — **обязательно** новый `rooms.json` + кадры «открыто» той же комнаты. Плюс раскладка «сцена почти во весь экран» для телефона и десктопа |
| B — метки зон | Описание состояний + значения для `tokens.json`; при силуэтном решении — образец на 2–3 зонах и оценка объёма масок |
| C — движение | Обновлённые `openZone` / `closeZone` в `motion.json`, фазы с кривыми; поведение при reduced-motion |
| D — тексты | `messages-ru-current.json` с переписанными значениями (ключи прежние) + памятка тона |

Всё, что меняет геометрию, присылай **комплектом** (кадры + rooms.json +
кадры «открыто»), иначе продукт не соберётся.
