# 36 — Сверка доски дизайна с продуктом: что решено, но не сделано

**What to build:** Реестр расхождений между макетом дизайн-сессии и тем, что
реально работает. Не код — документ, из которого рождаются тикеты.

**Blocked by:** —

**Status:** todo

## Зачем

Доска (`design/package/Main Screen.dc.html`, 658 КБ, 22 турна) содержит
решения, которых нет ни в `handoff/*.json`, ни в README — они живут только
текстом внутри макета. Мы читали её выборочно, и это уже дало осечку:
владелец напомнил про настройки цен в зале славы (турн 12), а мы отвечали
по коду и спецификации, где их нет. Такие «мы же договаривались» будут
всплывать и дальше, пока доска не разобрана целиком.

Контракты `handoff/` описывают **как рисовать**. Доска описывает **что
решено**. Второе нигде не сведено.

## Что сделать

1. Пройти все 22 турна по `handoff/README.md → Инвентарь экранов`.
   Текст из макета вынимается вместе с разметкой — читать надо очищенный.
2. Для каждого турна выписать **решения продукта**: правила, настройки,
   состояния, тексты — всё, что человек увидит или сможет переключить.
3. Каждое решение сверить с кодом: **есть / нет / сделано иначе**.
4. Результат — `docs/design-board-gaps.md`: таблица «турн · решение ·
   состояние · где в коде · что делать».
5. Расхождения разложить по важности: ломает продукт / заметно человеку /
   косметика. Из первых двух групп сразу предложить тикеты списком.
