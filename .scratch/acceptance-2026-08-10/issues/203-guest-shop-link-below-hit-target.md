# 203 — обычная строка «Где купить» у гостя ниже контрактной цели нажатия

**Откуда:** найдено при написании телефонного e2e на карточки вещи (тикет 196).
Границу того тикета исполнитель держал правильно и продукт не трогал.

## Число

Живой замер на телефоне, гостевая карточка:

| элемент | высота | контракт |
|---|---|---|
| обычная строка «Где купить» (`ShopLink place="sheet"`) | **39.6** | 44 |
| главная дверь при скрытой цене (`place="door"`) | 52.4 | 44 ✓ |

То есть правило соблюдено там, где блок переделывали пакетом 46, и **не
соблюдено там, где строка осталась прежней**.

`hitTargetMin: 44` — число контракта (`handoff/rooms.json`), а не вкус: у него
своя проверка в спеке настроек и в e2e, и он держится везде, кроме этого
места.

## Почему это заметно именно у гостя

У гостя «Где купить» — часть пути к покупке, а не справка: он пришёл дарить, и
эта ссылка одна из двух вещей, ради которых он на экране (вторая — бирка).
Промах по 39.6 на ходу стоит ему второй попытки.

У хозяйки та же строка живёт в свёрнутом блоке и нажимается реже — но правило
одно на обоих, и разводить их незачем.

## Решение

Поднять цель `ShopLink` вида `sheet` до 44 **не увеличивая видимый текст**:
цель нажатия и рисунок — разные вещи. Годится вертикальный отступ внутри
ссылки либо псевдоэлемент, растягивающий область нажатия; выбрать по месту,
чтобы не разъехалась строка рядом стоящих блоков.

**Проверить остальные виды `ShopLink`** заодно: `tile` (плитка вещи) и `card`.
Если и там ниже 44 — поднять все, счёт в отчёте.

## Границы

- Три обязательства блока (тикет 37) не расщеплять: `rel`, запись перехода,
  разбор домена остаются на месте.
- Слова не менять.
- Главную дверь (`door`) не трогать — там 52.4, всё верно.

## Проверка

- замер живьём на телефоне: каждый вид `ShopLink` ≥ 44 — шагом в
  `e2e/mobile-layout.spec.ts`, рядом с уже существующей проверкой целей
  карточки;
- видимый текст строки не вырос — замер до и после;
- `npm run test`, `npm run lint`, `npm run typecheck`.
