# 189 — «Что чаще всего хочется?»: четыре нажатия, ноль видимых последствий

**Откуда:** приёмка владельца 11.08.2026, пункт 3б из шести:

> «Если первый раз попадаешь как новый пользователь, то не ясно, зачем выбор,
> что хочется больше всего? … б) ничего не происходит и непонятно, на что это
> влияет»

## Владелец описал механизм точно

`src/app/room/starter-pack.tsx:95` — нажатие по чипу молча уезжает на сервер:

```js
startTransition(async () => { await saveWantsAction(next); });
```

Кнопки «готово» нет по замыслу, подтверждения нет, экран не меняется ничем.
Ответ красит **ровно две вещи**, и обе невидимы в момент ответа:

1. порядок наполнения стартовым набором — то есть **тем самым автонаполнением,
   которое тикет 191 выпиливает целиком**;
2. порядок зон в форме добавления вещи — увидеть можно только уйдя на другой
   экран.

То есть после тикета 191 у вопроса остаётся один эффект, и он проявляется на
другом экране через несколько шагов. Человек нажимает четыре раза и не
получает ничего — ровно как владелец и говорит.

## Решение: вопрос уходит вместе с набором

Держать анкету, единственный видимый результат которой мы сами убираем, —
нечестно к человеку и дорого нам.

1. Блок чипов, `Onboarding.wantsTitle/wantsSubtitle/wantsMax`,
   `saveWantsAction`, `starterPackWantsAction` и отметка
   `STARTER_WANTS_ASKED_KEY` уходят вместе с компонентом (тикет 191);
2. **порядок зон в форме добавления считается по делам, а не по анкете:**
   зоны, куда человек уже клал вещи, идут первыми, остальные — контрактным
   порядком. Это точнее анкеты и не стоит человеку ни одного нажатия;
3. поле `wants` в комнате: чтением больше не пользуемся. Данные не стираем —
   миграция удаления необратима, а польза от неё нулевая; поле остаётся
   мёртвым до отдельного решения.

## История, чтобы не завести это снова

Вопрос уже переезжал: был четвёртым шагом онбординга (тикет 113, доска 34b),
дизайн сам предложил убрать его с отдельного экрана (письмо 33, турн 40b):
«после v2 стартовый набор ужался вдвое — цена целого экрана выше пользы».

**Это второй раз, когда вопрос не оправдал места.** Первый раз его ужали,
теперь убираем: причина та же и названа была верно ещё тогда.

## Границы

- Порядок зон в форме добавления — только сортировка. Ни одна зона не
  пропадает и не появляется, набор зон комнаты не трогается.
- Заготовки полок (`ZoneSet`) — не это. Их выбирают в настройках, и они
  остаются.

## Проверка

- новый пользователь на пустой комнате не видит ни одного вопроса без
  видимого ответа;
- форма добавления показывает первой зону, куда человек уже клал вещь, —
  тест на сервисе, не на разметке;
- у комнаты без единой вещи порядок зон контрактный — тест;
- мёртвых вызовов `saveWantsAction` не осталось — `grep` по `src/`;
- `npm run test`, `npm run lint`, `npm run typecheck`.

**Зависимость:** делать вместе с тикетом 191 или сразу после него — файл один.
