# 175 — посев стенда: половина «хочется» — из контракта, витрина остаётся на демо-пулах

**Откуда:** хвост из передачи («посев стенда на 95 зёрен контракта, не начат»).
Тикет 136 перенёс зёрна «начни с готового» из кода в контракт дизайна
(`design/package/handoff/seeds/seeds.json`, 19 пулов ровно по 5 = 95 зёрен с
кадрами), но посев стенда остался на `src/config/demo-pools.ts`.

## Разбор: отказ был прав только наполовину

`src/server/services/stand-seed.ts` и `src/server/services/pack-seeds.ts`
объясняют отказ дословно так: «стенду нужны ОБА МЕСТА — и вещи комнаты, и
сокровищница с дарителем и годом; зерна „уже своё“ в контракте набора нет и
быть не должно (инвариант №2)».

Довод верен — но он покрывает **только витрину**. Половину «чего хочется»
контракт закрывает полностью: там ровно те же 19 пулов по 5 зёрен, с кадрами.
То есть сегодня владелец смотрит на стенде вещи, которые **придумали мы**, а
живой человек по кнопке «начни с готового» получает вещи из контракта — две
разные комнаты. Стенд для того и стоит, чтобы показывать продукт, а не наш
черновик.

## Решение

**Комната сеется контрактом, сокровищница — демо-пулами.**

- зёрна «хочется» берутся `livePoolSeeds` (контракт), как у живого человека;
- зёрна с признаками «уже моё» / даритель / год берутся из `demoPools` и
  кладутся в сокровищницу тем же `createItem` со входом «сразу в сокровищницу»
  (тикет 89) — как сейчас;
- граница между половинами — **признак зерна, а не список файлов**: демо-пул
  отдаёт в посев только те зёрна, у которых есть «уже своё»; всё остальное
  оттуда больше не берётся. Тогда правило читается одной фразой и не разъедется,
  когда дизайн пришлёт следующие 95.

## Что не менять

1. **Ни одной прямой записи в `prisma.item`.** Вещи создаёт `createItem` —
   посев ходит продуктовыми дверями. Это правило файла, не трогать.
2. **Идемпотентность «сеем только в пустую зону»** остаётся ровно такой.
3. **Защита** (`QUICK_LOGIN_ENABLED` + почта из окружения) — не трогать.
4. **Посев только добавляет** — ни одного удаления и ни одного update чужого
   поля.
5. Зона-витрина `anything` и добор `SPILLOVER_PREFERENCE` (`watches`/`jewel`) —
   логика остаётся; проверить, что она жива, когда пул приходит из контракта
   (форма зерна другая: `{ name, price, photo? }` без «уже своё»).
6. Пула `money` нет ни там, ни там — и не выдумывать: в зоне копилка.

## Риск, который проверить руками

Контрактные кадры лежат тем же `refs/p-*.jpg`, что и демо — но **сверить, что
каждый `photo` из `seeds.json` действительно есть файлом** в
`design/package/refs/`. Зерно с несуществующим кадром не должно ронять посев
целиком: пропускать кадр, вещь заводить, пропуск считать и вернуть числом в
отчёте `/dev-login?report=1`. Молча — нельзя.

## Проверка

- `npx vitest run tests/stand-seed.test.ts tests/pack-seeds.test.ts
  tests/quick-login.test.ts` (и всё, что найдётся по `grep` на `seedStandRoom`);
- полный `npm run test` перед коммитом;
- `npm run lint`, `npm run typecheck`;
- **числом:** после правки посев на чистой комнате обязан дать столько же вещей
  комнаты, сколько раньше, или больше, и НЕ МЕНЬШЕ одной вещи в сокровищнице.
  Число вещей до и после назвать в отчёте.

Живой пересев стенда делает ведущий (`/dev-login?fresh=1`, затем второй заход
без параметров) — агенту в сеть не ходить.
