**Логотип приехал 09.08.2026, раундом 25.** Лежит в

То есть ждать нечего уже трое суток, и никто этого не заметил, потому что
ждущий комментарий никто не перечитывал. **Третий случай того же класса за два

тот файл или комментарий, который только читают.

## Почему это стоит сделать сейчас

Ссылку на комнату отдают **в мессенджере** — это единственный способ, которым
гость вообще попадает в продукт (друзья не добавляются, инвариант №4). Сейчас
в карточке ссылки имя площадки и описание есть, картинки нет: в ленте чата
комната выглядит как текстовая строка среди чужих превью с картинками.

## Что сделать

1. **Статическая OG-картинка площадки** из канонического локапа — для главной,
   входа и прочих не-комнатных страниц. Брать `grace-lockup-outlined.svg`,
   больше ниоткуда (в `design/round13/logo/` лежат два МЁРТВЫХ файла с живым
   `<text>` и семейством, которого нет — их README пакета прямо запрещает);
2. **OG комнаты** — с именем хозяйки: карточка ссылки должна говорить, чья это
   комната, потому что её отдают лично. Размер канона 1200×630.
   `src/app/r/[slug]/page.tsx` уже отдаёт свой `openGraph` — картинку добавить
   туда же;
3. **Комнату гостя в sitemap не пускать** (инвариант №7) — OG этого не меняет,
   но проверить, что добавление картинки не потянуло за собой индексацию;
4. снять из `layout.tsx` комментарий про ожидание — он и есть тот файл,
   который врал.

## Границы

- Изображения комнат неприкосновенны: OG комнаты собирается из локапа и имени,
  а не из кадра интерьера. Кадр — это её пространство, а не обложка.
- Ни одной новой крупной зависимости: если генерация картинки на лету тянет
  тяжёлое — класть статику.
- Имя площадки берётся из `Brand.name` одним ключом, как везде.

## Проверка

- карточка ссылки на комнату содержит картинку и имя хозяйки — проверить
  разметкой `<meta>`, а не глазами в мессенджере;
- ни один мёртвый файл логотипа не попал в сборку — `grep` по
  `design/round13/logo`;
- комната гостя по-прежнему не в sitemap;
- `npm run test`, `npm run lint`, `npm run typecheck`.
