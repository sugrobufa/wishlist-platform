# 158 — письма e2e собирались от ЧУЖОГО адреса: `webServer.env` до них не доезжает

**Откуда:** постановка владельца 10.08.2026, наблюдение при закрытии тикета 155.
Комментарий `playwright.config.ts` обещал: «Абсолютные ссылки (письма, OG)
собираются от адреса e2e-сервера», а в перехваченном письме прогона стояло:

    ✉  [письмо] hostess-e2e@wishlist.local
       Тема: Праздник прошёл — посмотри, что подарили
       Открой «что подарили»: http://localhost:3000/room/occasion

Не загрязнение от соседнего dev-сервера: то же воспроизвелось в изолированном
чекауте.

## Что там было

Подозрение из постановки — «`.env` через `loadEnvConfig` перебивает переменную,
переданную процессу» — **не подтвердилось**. Никто ничего не перебивает:

| проверка | значение |
|---|---|
| `APP_BASE_URL=…:3100 node -e "require('dotenv/config')"` | `http://localhost:3100` |
| то же без переменной в процессе | `http://localhost:3000` (из `.env`) |
| `APP_BASE_URL=…:3100` + `loadEnvConfig` из `@next/env` | `http://localhost:3100` |
| то же без переменной в процессе | `http://localhost:3000` (из `.env`) |

И dotenv, и `@next/env` заполняют только ПУСТОЕ место: заданную процессу
переменную они не трогают. Сервер это и подтверждает — поднятый ровно с
окружением `webServer.env` (`PORT=3100 NEXT_DIST_DIR=.next/e2e
APP_BASE_URL=http://localhost:3100`) он отдаёт свой же адрес:

    :3100 → <meta property="og:image" content="http://localhost:3100/rooms/v4-cream.jpg"/>
    :3000 → <meta property="og:image" content="http://localhost:3000/rooms/v4-cream.jpg"/>   (контроль, обычный dev)

**Побеждает не `.env`. Письмо просто рендерится не там, где мы думали.**
Прогон с временным логом внутри мини-воркера (`2 passed (1.3m)`, зелёный при
неверном хосте):

    [ДИАГНОЗ 158] модуль спека: pid=20100 APP_BASE_URL=http://localhost:3000
    [ДИАГНОЗ 158] модуль спека: pid=29008 APP_BASE_URL=http://localhost:3000
    [ДИАГНОЗ 158] джоба «occasion-owner»: pid=29008
        APP_BASE_URL=http://localhost:3000 appUrl=http://localhost:3000/room/occasion

pid 29008 — это worker-процесс Playwright, тот самый, где живёт мини-воркер
очереди mail (`e2e/full-cycle.spec.ts`: `new Worker(MAIL_QUEUE_NAME, …)` →
`processMailJob` → `appUrl`, `src/worker/mail.ts:93`). Процесс Next тут вообще
ни при чём, а `webServer.env` — это окружение ТОЛЬКО его: до процесса теста оно
не доезжает и не может доехать. В этом процессе адрес не задал никто, поэтому
дырку заполнил `.env` — `http://localhost:3000`.

В CI то же самое, только из другого места: в `e2e.yml` переменной `APP_BASE_URL`
нет вовсе и `.env` там не лежит — ссылка собиралась от зашитого дефолта
`http://localhost:3000` в `mailer.ts:122`. Ночной прогон был зелёный так же
молча.

Второе, не менее важное: **шов не проверял никто**. Шаг «письмо occasion-owner
лежит в E2E_MAIL_FILE» смотрел «кому» и «тему», внутрь письма не заглядывал, а
в записи NDJSON текста письма и не было.

## Делаем

Решение 1 из трёх предложенных — **отдать процессу теста тот же адрес**:

- `e2e/full-cycle.spec.ts` — `process.env.APP_BASE_URL = E2E_BASE_URL` рядом с
  такой же строкой про `E2E_MAIL_FILE` (шов писем там же и по той же причине:
  письма шлёт ЭТОТ процесс);
- `playwright.config.ts` — комментарий переписан честно: `webServer.env` даёт
  адрес СЕРВЕРУ (OG комнаты гостя), письма приходят не отсюда;
- `src/server/mailer.ts` — запись перехвата письма получила поле `text`, чтобы
  прогон мог проверить ссылку в самом письме.

Почему не два других решения:

- **«брать адрес из запроса/сервера» (2) невозможно у писем.** У джобы очереди
  запроса нет вовсе: письмо рождается из закрытия праздника, а не из чьего-то
  захода. В проде воркер (`npm run worker`) — отдельный процесс без Next, и
  адрес ему приходит только из окружения. Это устройство, а не недосмотр;
  менять его ради e2e нельзя. (Для OG на странице комнаты вариант 2 был бы
  уместен — но там всё и так верно.)
- **«снять обещание» (3) оставляет мину.** Ссылка письма вела бы на
  `http://localhost:3000` — адрес ЧУЖОГО dev-сервера, который прогон по
  контракту тикета 15 не трогает. Сегодня по ней никто не ходит, завтра шаг
  «перейди по ссылке из письма» уведёт тест на чужой стенд с чужой БД.
  Обещание дешевле выполнить, чем снять.

## Осторожно

1. **`webServer.env` — окружение процесса Next, и только его.** Всё, что
   рендерится в процессе теста (мини-воркер очереди, прямые вызовы сервисов),
   про эти переменные не знает. Ровно так же уже сделан `E2E_MAIL_FILE` —
   строка рядом, это не исключение, а правило стенда.
2. **`.env` ничего не перебивает — не «чинить» это в обратную сторону.**
   Соблазн добавить `override: true` или вычистить `APP_BASE_URL` из `.env`
   сломал бы обычный `npm run dev`, а причины не касается.
3. **Текст письма в NDJSON** пишется только при заданном `E2E_MAIL_FILE`, то
   есть в прогоне; файл лежит в `test-results/` (в `.gitignore`). Инвариант №1
   не задет: письмо хозяйке по-прежнему не содержит ни имён гостей, ни вещей —
   это держит `tests/mailer.worker.test.ts`.
4. **Магический вход был исправен и до правки**: его ссылку собирает сам Next
   из запроса (`http://localhost:3100/signin/confirm?…` в файле перехвата) —
   поэтому симптом и выглядел выборочным.

## Тест

Держит теперь три проверки — по одной на каждый слой:

- **прогон, `e2e/full-cycle.spec.ts`** — в перехваченном письме
  `occasion-owner` ссылка `${E2E_BASE_URL}/room/occasion`, и НИ ОДНА ссылка
  всех записей файла перехвата (включая magic link) не ведёт на чужой адрес.
  Проверка читает то самое письмо, в котором владелец увидел `:3000`;
- **`tests/mailer.test.ts`** — шов перехвата пишет ТЕКСТ письма одной строкой
  NDJSON (без него прогону не на что смотреть);
- **`tests/mailer.worker.test.ts`** — `occasion-owner` строит ссылку от
  `APP_BASE_URL` ПРОЦЕССА, который крутит воркер: подменили окружение на
  `:3100` — ссылка ровно `http://localhost:3100/room/occasion`.

**Красное проверено, не на словах.** Со снятой строкой присваивания прогон
падает ровно на шаге письма:

    Error: ссылка письма собрана не от адреса e2e-стенда
    Expected substring: "http://localhost:3100/room/occasion"
    Received string:    "Привет … Открой «что подарили»: http://localhost:3000/room/occasion …"

Числа прогонов:

| прогон | результат |
|---|---|
| до правки, с временным логом | `2 passed (1.3m)` — **зелёный при неверном хосте** |
| после правки, весь набор | `6 passed (5.5m)`, в письме `http://localhost:3100/room/occasion` |
| после правки, строка снята | `1 failed`, шаг письма |
| `npx vitest run` | 1503 из 1504 |
| `npm run typecheck` | чисто |
| `npm run lint` | 0 ошибок (2 старых предупреждения в `scripts/`) |

Единственный красный юнит — `tests/zone-row-mobile.test.ts` (строка зоны на
телефоне): он красный и на чистом `HEAD`, к письмам отношения не имеет и лежит
в работе соседнего агента (`src/components/zone-row/`).

**Где гонялось.** В рабочем дереве в этот час сосед переписывал
`src/components/scene/empty-places.ts` под пакет раунда 37, и сцена падала на
разборе `places.json` — прогон умирал до писем не по нашей вине. Поэтому оба
прогона (зелёный и красный) сделаны в ОТДЕЛЬНОМ чекауте: `git worktree` на
`HEAD` плюс только пять наших файлов. Чужого не тронуто ничего.
