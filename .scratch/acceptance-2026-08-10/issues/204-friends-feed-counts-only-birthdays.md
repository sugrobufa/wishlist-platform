# 204 — лента друзей считает только дни рождения, а праздников теперь три вида

**Откуда:** найдено при разборе остатков после тикета 198. Не приёмка, не
пакет — следствие вчерашней работы, которое никто не заказывал и никто бы не
заметил до первого Нового года.

## Что разошлось

Тикет 198 завёл три вида праздника: день рождения, общие даты (Новый год,
8 марта, 23 февраля) и свой повод. В комнате хозяйки ближайший из НИХ ВСЕХ
считает `nearestRoomOccasion` (`src/server/services/room-occasions.ts:127`).

**А лента друзей считает по-старому — только день рождения:**

```
src/server/services/connections.ts:801
  occasionDate: nextOccasionDay(birthdayOf(other.room), now)
```

`nearestRoomOccasion` зовётся ровно из одного места — `src/app/room/page.tsx:123`.

## Чем это плохо на экране

1. **Два разных ответа на один вопрос.** Ирина открыла своей комнате Новый
   год — у себя она видит «Новый год · 31 декабря», а друг в ленте видит её
   день рождения в марте. Кто из двух прав, человеку неоткуда узнать.
2. **Хуже: у кого нет дня рождения, в ленте нет НИЧЕГО.** Дату можно не
   заводить — «Пока не знаю» есть в онбординге и работает. Такой человек
   принял 8 марта, комната его ждёт, а лента друзей молчит: подарить некому и
   незачем. Это прямая потеря того, ради чего лента существует.
3. Порядок ленты (`feed-order.ts:42`) сортирует по `daysLeft` — то есть
   сортирует по неполным данным.

## Решение

Лента спрашивает то же, что и комната: **ближайший праздник ЛЮБОГО вида**.

1. `connections.ts` берёт дату из общего места — `nearestRoomOccasion` (или
   его чистой половины, если тянуть сервис в ленту дорого по запросам);
2. **имя праздника едет вместе с датой.** Сейчас поле называется
   `occasionDate` и несёт только день; «через 5 дней» без имени было терпимо,
   пока праздник был один, а теперь «через 5 дней» может быть и днём
   рождения, и 23 февраля — разница для дарящего существенная;
3. считать **одним проходом**: лента уже собирает комнаты пачкой, и запрос на
   каждую строку здесь заведётся незаметно (`N+1`).

## Границы

- **Инвариант №1 не трогать:** лента и так не говорит о бронях ничего, и
  праздники этого не меняют.
- Свой повод виден в ленте так же, как остальные: он не тайна, его завела сама
  хозяйка. Но проверить это отдельно — если решим иначе, это решение владельца,
  а не умолчание.
- Порядок разделов ленты не трогать.

## Проверка

- у комнаты без дня рождения, но с принятым общим праздником, в ленте есть
  дата — тест (сегодня её нет, и это главный случай);
- комната и лента дают ОДНУ И ТУ ЖЕ ближайшую дату — тест, сравнивающий два
  источника напрямую;
- имя праздника доезжает до строки ленты;
- число запросов на ленту не выросло — тест или замер;
- `npm run test`, `npm run lint`, `npm run typecheck`.
