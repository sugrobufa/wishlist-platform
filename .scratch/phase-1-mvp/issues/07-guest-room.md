# 07 — Комната гостя: /r/{slug}, guest-DTO, OG

**What to build:** Гость открывает `/r/{slug}` без регистрации и видит комнату
глазами гостя: та же сцена и зоны, но без спрятанных вещей, без выключенных
зон, без цен «люблю»; цены «хочу» — по настройке видимости. Красивое
OG-превью в мессенджерах.

**Blocked by:** 03.

**Status:** done

- [x] Маршрут /r/{slug} (код или ник; старый код после смены ника — 301 на ник)
- [x] guest-DTO: hidden и выключенные зоны отфильтрованы на сервере (тест «не течёт»); LOVE без цены всегда; WANT-цена по priceVisibility (FRIENDS в Phase 1 трактуется как ALL — связи-градация придёт позже, зафиксировать TODO)
- [x] Страница кэшируема (ISR + revalidateTag по мутациям хозяйки); динамика броней НЕ в этом кэше
- [x] OG-теги: имя хозяйки, кадр комнаты, счётчики вещей; непубличное не светится
- [x] Демо-призраки видны гостю тоже (комната новичка не мёртвая), но помечены и не бронируются

## Comments

- Сделано: `/r/{slug}` — полная комната гостя: та же сцена (SceneStage, контракт
  тикета 02: preset + zonesOff + zoneContent) и те же сетки зон (ZoneGrid,
  enterDelay="scene"), но данные приходят из нового сервиса
  `getGuestRoom(slug)` уже отфильтрованными для гостя. Страница не вызывает
  auth() и не читает cookie — HTML одинаков для всех (регистрация «по пути» —
  тикет 08); `robots: noindex, nofollow` (инвариант №7) стоит и на живой
  комнате, и на неизвестном слаге; неизвестный/мусорный слаг — 404.
- Серверная фильтрация (инвариант №5, всё под тестами):
  - hidden отсекается в самом SQL (`where hidden: false`) — спрятанное не
    попадает даже в кэш;
  - зоны из zonesOff выбрасываются целиком ПОСЛЕ кэша по свежей строке
    комнаты на каждом запросе (тем же `visibleZones`, что прячет мебель в
    сцене) — даже устаревший кэш вещей не покажет гостю выключенную зону;
  - демо-призраки — зонам, пустым в глазах гостя: выдача — чистая функция
    видимых гостю данных, наличие спрятанных вещей картинку не меняет (нет
    побочного канала «в этой зоне что-то спрятано»; зона, где всё спрятано,
    выглядит для гостя как пустая — призраки с бейджем «пример»).
- guest-DTO (`itemForGuest`, `ghostForGuest`) — структурное подмножество
  owner-DTO, ZoneGrid берёт его как есть (компайл-проверка в тестах):
  WANT = {id, zone, state, title, note, photoUrl, isDemo, size, color, desire}
  + {price, currency} ТОЛЬКО при priceVisibility ∈ {ALL, FRIENDS} (FRIENDS в
  Phase 1 = ALL, TODO на градацию связей — в `guestSeesPrice`); LOVE =
  {…base, giverName, receivedAt, inHall} — ключей price/currency не существует
  (инвариант №8). Ключей hidden и priceVisibility в guest-формах НЕТ вовсе;
  booking-полей нет и не будет — «занято» придёт отдельным каналом (тикет 08).
- Кэш: тяжёлое чтение вещей обёрнуто в `unstable_cache` с тегом
  `room-${roomId}` (в кэше — только guest-DTO, чистый JSON); мутации хозяйки
  ревалидируют тег начиная с тикета 04 (вещи) и 13 (настройки).
  **Полностраничный ISR отложен в тикет 16**: динамический сегмент + params в
  Next 16 кладут страницу в full route cache без явного окна ревалидации, и
  до прихода revalidateTag во ВСЕ мутации (13 ещё не собран) гость мог бы
  видеть выключенную зону/спрятанную вещь из кэшированного HTML — это окно
  нарушения инварианта №5. Поэтому страница пока `force-dynamic` (SSR),
  свежие preset/zonesOff — каждый запрос, а дорогая часть (вещи) уже сидит в
  Data Cache под тегом; включение ISR потом — вопрос снятия одной строки.
- OG: `generateMetadata` → title «Комната {имя}», тихое description
