## Цифры

- **Тесты:** 400 юнит-тестов, 34 файла, все зелёные (рост по фазе:
  166 → 276 → 318 → 348 → 390 → 398 → 400). **e2e: 6 зелёных** (2 смоука × 2
  проекта phone/desktop, полный цикл ~30 с, перф-замер) — прогон ~48 с.
- **Perf комнаты гостя** (DoD: Lighthouse mobile ≥90):
  - dev-сервер (тикет 15, для истории): performance **51**, LCP 7.0 с — топили
    неминифицированные бандлы;
  - прод-сборка ДО полировки: **80** (FCP 1.9 с, LCP 3.8 с, TBT 320 мс) —
    LCP-кадр комнаты живёт CSS-фоном и стартовал только после гидрации;
  - прод-сборка ПОСЛЕ (preload кадра из HTML, fetchPriority=high): **90**
    (медиана 6 прогонов, разброс 87–90 на вариации TBT; FCP 2.4 с, LCP 2.7 с,
    TBT 190–250 мс, CLS 0, вес 404 KiB). A/B: без fetchPriority=high LCP
    откатывается к 3.8 с (браузер держит preload картинки за скриптами).
  - Первый экран сцены: 193 KiB ≤ бюджета 2 МБ (ассерт в e2e).
- **Коммиты:** 25 до финального (Phase 0 — 3, спека+тикеты — 1, Phase 1 —
  остальные); финальный коммит фазы — за владельцем.
- **Миграции БД:** 3 (`init`, `room_nick_demo_toggle`,
  `occasion_unique_room_date`).
- **Метрики PRD §11** — готовые запросы `docs/metrics.sql`, все прогнаны на
  dev-БД (валидность математики проверена на синтетике в откатанной
  транзакции): активация ≥3 вещей/7 дней, доля «люблю» (среднее+медиана по
  комнатам), шаринг, ≥1 бронь/30 дней, замыкание цикла, качество парсера.

## Что сознательно НЕ вошло (и почему)

Из Out of Scope спеки (запланированно):
- UI складчины и координация — Phase 2 (каркас POOL в БД готов; деньги через
  сервис не ходят никогда — решение владельца);
- Playwright-fallback парсера и адаптеры магазинов — Phase 2 (фикстуры уже в
  репо);
- PWA share_target, price.refresh, каталог фидов, AI-распознавание, стриминги,
  передача комнаты, поиск, англ. строки (каркас en есть) — по ROADMAP;
- 3D зала славы — отвергнут (ADR-0001): фото + CSS-вращение сейчас,
  2.5D-параллакс в Phase 2.

Переносы полировки (решение тикета 16, всё перечислено и в ROADMAP):
- **S3-сироты при живом аккаунте** (deleteItem/смена аватара/замена фото) и
  **ретрай s3Cleaned:false** после удаления аккаунта → джоба `s3.cleanup`
  поверх готовых кирпичей `listKeysByPrefix`/`deleteObjects` (src/server/s3.ts);
- **sharp** (resize ≤1600 + AVIF/WebP в image.ingest, квадрат аватара) — в
  Phase 1 без новых зависимостей; TODO стоит в src/worker/image-ingest.ts;
- **экран согласия «остаться на связи»** (мок 20a) — связь создаётся сразу
  при «Дошло» (README пакета, турн 20); «Позвать» у «смотрели» — нет канала
  приглашений в Phase 1;
- **«укрепление» вторым способом входа** перед первым шером — поле
  `User.secondAuth` в схеме есть, флоу не строился.

## Допущения и решения конвейера (с датами)

- **2026-08-04, гриллинг:** рынок — РФ (фикстуры Ozon/WB/ЯМ/Lamoda/ЗЯ/DNS;
  Telegram — кандидат «укрепления»).
- **2026-08-04, гриллинг:** деньги через сервис не ходят никогда; складчина —
  только координация договорённостей.

## Известные ограничения

- **Хотспоты трёх мужских комнат размечены «на глаз»** (метка дизайн-пакета) —
  визуальная сверка с кадрами не делалась; запланирована в Phase 2 ROADMAP.
- **FRIENDS = ALL** — градация придёт со связями-уровнями.
- **Живые Ozon/WB из датацентра отдают анти-бот** — парсер честно отдаёт
  «честную карточку» (дозаполнение руками); разбор проверен фикстурами;
  клик-проверка из резидентного браузера — за владельцем.
- **Метрики — нижние оценки:** событийного лога нет, Booking-строки живые
  (снятая/закрытая бронь исчезает), анонимные визиты не хранятся; оговорки и
  прокси прописаны в `docs/metrics.sql`, точная версия — события/PostHog
  (Phase 2).
- **Правки полей после парсинга не трекаются** — метрика качества парсера
  считается прокси (доля URL-вещей, доля с фото/ценой); в Phase 2 — флаг
  «сохранена без правок» при сабмите формы (форма знает, что трогали руками).
- **revalidateTag из воркера не достаёт до кэша Next** (отдельный процесс без
  общего cache handler) — закрыто окном ревалидации 300 с; при переезде на
  общий cache handler (мульти-инстанс) заработает мгновенно.
- **ISR кэширует и 404 мусорных слагов** (диск, окно 300 с) — приемлемо для
  self-hosted; при выходе за CDN добавить rate limit на /r/*.
- **Клиент получает весь словарь next-intl** (~весь ru.json в HTML) — диета
  по namespace'ам — дешёвый перф-кандидат Phase 2 (заметный вклад в TBT).
- **Экспорт GDPR отдаёт ключи файлов, не сами файлы** — zip с фото по первому
  запросу пользователей.
- **Письмо occasion-owner строит URL от APP_BASE_URL процесса-воркера** — в
  проде URL один, в dev может отличаться от e2e-порта (на ассерты не влияет).
- **Приватный бакет распознавания** (RecognitionJob.imageKey) чисткой не
  покрыт — фича мертва за флагом до Phase 2; строки БД удаляются.

## Рекомендованные первые шаги Phase 2

1. **Джоба s3.cleanup + sharp в image.ingest** — оба TODO готовы к приёму
   (кирпичи в s3.ts, шов в воркере); закрывает сирот и даёт AVIF/WebP для
   фото вещей (перф-запас LCP на реальных комнатах).

   «сохранена без правок» — метрики §11 перестают быть нижними оценками.
3. **Складчина-координация** (P1-экран): каркас POOL и origin pool:{id} в
   схеме уже зарезервированы; деньги не ходят — только договорённости.
4. **Playwright-fallback парсера + адаптеры** топ-магазинов РФ (фикстуры и
   изолированный модуль готовы) — целим ≥80% URL без ручной правки.
5. **Сверка хотспотов мужских комнат** с кадрами (три M-пресета) — долг
   дизайн-пакета.
6. **Перф-диета:** next-intl namespaces клиенту; AVIF-варианты кадров комнат —
   потребует отдельного решения владельца (кадры неприкосновенны по

7. **Градация FRIENDS** поверх связей (kind уже есть) + индексация/OG-политика
   комнат (открытый вопрос PRD §12.3).
