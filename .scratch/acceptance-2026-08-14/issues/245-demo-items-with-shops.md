# 245 — на стенде блок «Где купить» не видно ни на одной вещи

**Откуда:** приёмка владельца 14.08.2026.

> «Также накидай в тестовые данные товаров с точками продаж. Сейчас совершенно
> не вижу, как выглядит этот блок на любом предмете.»

## Что сейчас

Блок собран с тикета 37 и работает в трёх местах (карточка хозяйки строкой,
карточка гостя раскрытой, лист брони). Показывать ему нечего: посев стенда
зовёт `createItem` без `url` (`pack-seeds.ts → createInputFor`), а руками
ссылку было не добавить вовсе — это тикет 244. Ни одна демо-вещь ссылки не
имеет, поэтому блока нет ни на одном экране стенда.

## Что сделать

1. `DemoSeed` для вещи КОМНАТЫ получает необязательный `url`; `createInputFor`
   доносит его до `createItem`.
2. Ссылки проставить **в разных пулах**, а не в одном: иначе блок виден на
   одном экране и замечание закрыто наполовину. Домены — те шесть, что знает
   парсер (`AddItem.urlShops`).
3. **Адреса ведут в разделы магазинов, а не в выдуманные карточки товаров.**
   Ссылка демо-вещи обязана открываться: стенд, который врёт нагляднее, чем
   учит, хуже пустого блока.

## Границы

- **Вещь сокровищницы ссылки не получает** — звать в магазин за тем, что уже
  подарено, другой продукт.
- `source` у демо-вещей остаётся ручным: их никто не парсил. Домен и
  канонический адрес всё равно считает сервер (правило тикета 195).
- Фото по ссылке не подтягивается: демо-кадры берутся из пакета.

## Проверка

- юнит: ссылок не меньше пяти и они в разных пулах;
- юнит: каждая — http(s) и из известных парсеру доменов;
- юнит: посев доносит ссылку до вещи комнаты и не даёт её вещи витрины;
- `npm run test`, `npm run lint`, `npm run typecheck`.
