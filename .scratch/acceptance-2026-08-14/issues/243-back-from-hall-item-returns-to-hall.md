# 243 — из вещи сокровищницы «назад» уводит в комнату мимо сокровищницы

**Откуда:** приёмка владельца 14.08.2026, тот же заход.

> «Сейчас, если я попадаю в вещь из сокровищницы, то при выходе назад я попадаю
> не в сокровищницу, а в список всей категории, а потом вообще в комнату.
> Нелогично.»

## Что сейчас

`src/app/room/zone/[zone]/i/[id]/item-card.tsx:273` — адрес возврата считается
одной строкой и не смотрит, откуда человек пришёл:

```ts
const zoneHref = `/room/zone/${item.zone}`;
```

Вход в карточку из витрины есть и он единственный: перо-заметка в
`hall-showcase.tsx:229` ведёт на `/room/zone/{zone}/i/{id}`. То есть человек
заходит из сокровищницы, а стрелка в шапке уводит его в полку комнаты — экран,
которого он не открывал. Дальше «назад» из полки ведёт в комнату, и дорога в
сокровищницу теряется совсем.

**Это не история браузера, а наша стрелка.** Кнопка — `<Link href>`, а не
`router.back()`, поэтому и чинится адресом, а не историей.

## Что сделать

1. Вещь витрины (`item.inHall`) возвращает в **`/room/hall`**; вещь комнаты —
   по-прежнему в свою полку. Подпись знака берётся из того же словаря:
   `Hall.toHall` («Сокровищница») против имени полки.
2. **Строку «стоит в „{полка}"» внизу карточки не трогать** — она не дорога
   назад, а указание места, и для вещи витрины остаётся верной: вернувшись в
   комнату, вещь встанет именно туда.

## Границы

- Второго входа в карточку витрины нет — проверено; если появится, правило
  «возврат по месту вещи, а не по адресу входа» останется верным.
- Гостевая карточка (`/r/[slug]/i/[id]`) этим тикетом не трогается: у гостя
  своя дорога и своё «назад».

## Проверка

- юнит: у вещи с `inHall: true` адрес возврата `/room/hall`, у вещи комнаты —
  `/room/zone/{zone}`;
- юнит: подпись знака возврата у витринной вещи — «Сокровищница»;
- `npm run test`, `npm run lint`, `npm run typecheck`.
