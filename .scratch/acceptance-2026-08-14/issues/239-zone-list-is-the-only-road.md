# 239 — список полок стал единственной дорогой к семи из них

**Откуда:** пакет 51, `handoff/round51/zone-list.json` (турн 57a).

> До сих пор список полок был удобством. Теперь это единственная дорога к семи
> полкам из 134 — и его нет ни в турнах, ни в списке P0.

Семь полок живут без места на кадре (тикет 235): `emerald/beauty`,
`sport/gaming`, `study/gaming`, `loft/gaming`, `gamer/bar`, `sport/bar`,
`loft/bar`. В кадре их нет, и попасть в них можно только списком.

## Главное решение экрана — он ничего не помечает

Дизайн отклонил подпись «на кадре её нет» своим же доводом:

> Это сообщение об отсутствии. Человек не знает, что у полки бывает место на
> кадре, и узнавать ему незачем — полка открывается, вещи внутри, всё работает.

**Следствие, которое стоит держать:** новое состояние не потребовало ни одного
нового знака. Потребовало бы — значит завели второй сорт полок, а не закрыли
дырку.

## Что сделать

1. Собрать экран по `zone-list.json` (числа и состав — оттуда, своих не
   заводить). Слова — раздел `ZoneList` в словаре пакета, 7 живых строк.
2. **Пустая полка обязана быть в списке.** Сегодня `RoomListView` отбрасывает
   группы без вещей («список про вещи») — и полка без места на кадре, пока она
   пуста, не видна НИГДЕ: ни в кадре, ни в списке. Это дыра, найденная тикетом
   235, и закрыть её должен этот тикет.
3. Проверить дорогу целиком: комната → список → полка без места → добавить
   первую вещь → она видна.

## Границы

- Никаких пометок «этой полки нет на кадре» — ни значком, ни подписью, ни
  порядком.
- Экран «зона целиком списком» (19b) — другой экран, его не трогать.
- Слов не сочинять: раздел `ZoneList` пришёл целиком.

## Проверка

- юнит: все полки комнаты в списке, включая пустые и включая без места;
- юнит: ни одна полка в списке не помечена ничем, что отличало бы её от
  соседей;
- сквозной: дорога «комната → список → пустая полка без места → первая вещь»;
- `npm run test`, `npm run lint`, `npm run typecheck`.
