### Вердикт: «Открыть почту» — НЕ строим

`mailto:` открывает НАПИСАНИЕ письма, а не входящие — не то действие. Веб-
ссылки на входящие по домену (gmail.com → mail.google.com, mail.ru →
e.mail.ru, …) — это и есть хардкод почтовых сервисов, который тикет
запрещает. Универсального способа «открыть входящие» у веба нет. Выписано.

### Вердикт: фолбэк-код — НЕ строить (исследование, без постройки)

Технически Auth.js позволяет: у email-провайдера есть
`generateVerificationToken` — токен можно сделать 6-значным кодом, а страница
подтверждения могла бы принять его руками POST-ом в тот же callback. Но:

1. **Токен один на ссылку и код.** Сделать ЕГО 6-значным — значит, ссылка
   перебирается: 10⁶ вариантов, callback Auth.js попыток не считает, токен
   живёт сутки. Прямая дыра в аккаунт.
2. **Безопасная версия — своя механика поверх Auth.js**: вторая запись
   VerificationToken (длинный токен в ссылку + короткий код), TTL кода 5–10
   минут, счётчик попыток с блокировкой (БД/Redis), лимит на IP — Auth.js
   ничего из этого не даёт из коробки.
3. Код должен попасть в письмо — mailer чужая территория.

Ценность сомнительна: наша схема и так открывает вход на любом устройстве
(страница подтверждения, GET ничего не тратит), код нужен только когда почта
живёт на другом устройстве. Если владелец захочет — отдельный тикет по
пунктам выше.
