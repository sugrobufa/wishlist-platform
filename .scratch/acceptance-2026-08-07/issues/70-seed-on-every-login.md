# 70 — Стенд наполняется сам, без волшебного параметра

**What to build:** Причина замечания 4 приёмки 07.08, найденная замером на
живом стенде. Владелец смотрит **демонстрационную** комнату — и там **все 13
зон пусты**: настоящих вещей ноль, в каждой зоне рисуются демо-призраки с
бейджем «ПРИМЕР».

Замер (`fetch` по всем зонам комнаты стенда, 07.08):

| зона | своих вещей | призраков |
|---|---|---|
| fashion, perfume, bags, travel, anything, events, books, flowers, home | 0 | по 4 |
| beauty, jewelry, music | 0 | по 5 |
| money | 0 | 0 (пула нет) |

**Status:** todo

## Почему так вышло

Посев (тикет 61) запускается **только** по адресу `/dev-login?seed=1`
(`quick-login.ts:314`: `attempt.seed ? await seedStandRoom(...) : null`).
Владелец входит обычной ссылкой `/dev-login` — и комната остаётся пустой
навсегда. Тикет 61 не сломан: он делает ровно то, что написано. Ошибка в
том, что наполненность стенда поставили в зависимость от того, вспомнит ли
человек параметр.

## Что сделать

**Посев — при каждом быстром входе, без параметра.** Он для этого уже
устроен: идемпотентен («сеем только в пустую зону»), только добавляет, ничего
не удаляет и ходит через `createItem` — те же продуктовые двери, что у формы.
Комната, где вещи уже есть, стоит 13 запросов `count` и ноль записей.

- в `attemptQuickLogin` сеять всегда, а не по `attempt.seed`;
- `?seed=1` оставить рабочим адресом — обратная совместимость закладок; он
  становится синонимом обычного входа, и это записать в шапке `dev-login`;
- `?fresh=1` не трогать: сброс сносит комнату, посев честно вернёт
  `roomFound: false`, владелец уезжает в `/onboarding`. Порядок «сначала
  стираем, потом сеем» уже соблюдён и остаётся;
- защита не ослабляется ни на шаг: посев по-прежнему работает **только** при
  `QUICK_LOGIN_ENABLED=true` и **только** для `QUICK_LOGIN_EMAIL` из
  окружения (это демо-почта `dem…@wishlist.local`, не личная почта
  владельца — его решение «личную комнату посевом не наполнять» соблюдено).

## Осторожно

- Ни один параметр запроса не должен начать влиять на то, КОГО наполняют.
  Почта берётся из окружения — это правило тикетов 29/31/61, не трогать.
- Не превращать посев в «наполнить всегда до конца»: правило «зона с вещами
  пропускается целиком» — то, чем он не затирает заведённое руками.
- Быстрый вход не должен заметно замедлиться: у полной комнаты это 13
  `count`. Если окажется дороже — замерить и написать число в Comments.
- Тесты `tests/quick-login.test.ts` и `tests/stand-seed.test.ts` ходят в БД:
  локально без Docker не идут, прогон — на CI.

## Критерии

- [ ] Вход по голому `/dev-login` наполняет пустую комнату стенда
- [ ] Повторный вход в наполненную комнату не создаёт дублей
- [ ] `?seed=1` продолжает работать и делает то же самое
- [ ] `?fresh=1` по-прежнему сбрасывает и уводит в онбординг
- [ ] Наполнять по-прежнему можно только демо-почту из окружения — тест
- [ ] На стенде после выката: во всех зонах свои вещи, бейджей «ПРИМЕР» нет
- [ ] CI зелёный (тесты с БД идут там)
