## Как проверять живьём — и чего в панели браузера УВИДЕТЬ НЕЛЬЗЯ

Локально: `docker compose up -d`, дев-сервер через панель браузера
(`preview_start`, конфигурация `web`), вход через `/dev-login` (сеет стенд
сам). Гостевая сторона — `/r/{shareSlug}`; слаг после `fresh=1` МЕНЯЕТСЯ,
`/r/demo` больше не работает — смотреть в БД.

**Панель скрыта и не композитит кадры.** Отсюда три следствия, на которых
легко потерять полчаса (потеряны на тикете 102):

- **анимации не идут вовсе**: переход, начатый переменной, «замирает» на
  первом значении — и наш сегмент нити, и давно работающий проезд комнаты
  выглядят одинаково сломанными. Это не CSS;
- **`requestAnimationFrame` не вызывается никогда** — скрипт с ним просто
  висит до таймаута. Ждать через `setTimeout`;
- **скриншоты не работают**, клик по координатам ненадёжен — жать элементы
  скриптом через `javascript_tool`.

**Что делать вместо этого:** проверять КАРТУ, а не движение — выключить
переход (`el.style.transition='none'`), подставить крайние значения и
замерить `getBoundingClientRect`. Так и проверена нить: 0 → 0, середина →
середина, конец → конец.

Ещё одно: страница комнаты у ВОШЕДШЕЙ хозяйки не покажет гостевых состояний
(канал «занято» ей отдаёт пустой список — инвариант №1). Гостевые проверки
делать `curl`-ом без cookie либо из другой сессии.
