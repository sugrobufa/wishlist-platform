# PRD — Wishlist Platform

Версия 0.3 · август 2026 · статус: принят дизайн-пакет
0.3: продукт зафиксирован по итогам дизайн-сессии. **Источник правды по UI и
поведению — `design/package/`** (интерактивный макет + handoff-контракты).
При конфликте этого документа с макетом и handoff — прав дизайн-пакет,
расхождение фиксируется здесь явной правкой.

## 1. Видение

**Комната** человека — его личное пространство, отрисованное как фотореальный
интерьер. Комната говорит не только «чего у меня нет» (вишлист), но и «что у
меня есть и что я люблю» — и этим объясняет гостю вкус хозяйки лучше любого
списка. Дизайн — ядро продукта: тёмная тёплая сцена, журнальная типографика,
материальные детали (полка светится, шкатулка поднимает крышку, бирка на нити).

Комната — не картинка, а место: на телефоне она **не уменьшается, а
приближается**; тап по зоне — шаг к ней, а не переход на другой экран.

Гость по ссылке «ходит» по комнате, понимает, что подарить, и **тихо бронирует**
подарок. После праздника цикл замыкается экраном «что подарили»: вещи
переезжают в зал славы, дарители раскрываются, появляются связи.

## 2. Модель контента: одна вещь, два состояния

Ядро продукта (контракт: `design/package/handoff/items.json`):

| | **«Люблю»** | **«Хочу»** |
|---|---|---|
| Смысл | Уже моё. Показываю, а не прошу | Хочу получить в подарок или купить |
| Цена | Не показывается — вместо неё «люблю» или «Подарен в 2024 · подарила мама» | Обязательна; показ настраивается (все / друзья / только я / никому) |
| Бронь гостем | Невозможна | Да, тихая |
| В комнате | Предмет плотный и освещён | Призрачный пунктирный контур, полка под ним светится |
| Доп. поля | даритель, дата | размер, цвет, «насколько хочется» (4 ступени) |
| Зал славы | Только «люблю» попадают туда | — |

- Вопрос «**Что это для тебя?**» задаётся в карточке добавления — вместо кнопки
  «добавить в вишлист».
- **Единственный переход** `хочу → люблю`: хозяйка отмечает «Дошло» на экране
  «что подарили». Три побочных эффекта: вещь уезжает в зал славы, раскрывается
  имя дарителя, предлагается «остаться на связи». Обратного перехода нет.
- Пунктир кодирует состояние «хочу», а НЕ отсутствие фото (частая ошибка,
  покрыть тестом).

## 3. Роли

- **Хозяйка/хозяин** — ведёт комнату: вещи, зоны, праздники.
- **Гость** — открывает комнату по ссылке без регистрации, смотрит, тихо
  бронирует; регистрация предлагается «по пути» (после брони/складчины).
- **Связь** — не «друг по заявке»: связь рождается из подарка или открытой
  ссылки (взаимно / слежу / смотрели).

## 4. Цикл дарения (ядро)

1. Гость бронирует вещь «хочу» — **тихо**: другие гости видят «занято»,
   хозяйка видит только счётчик «3 вещи уже забраны» — ни имён, ни вещей.
   Счётчик может убывать (отмена брони, несобравшаяся складчина) — хозяйка
   видит число, но не вещь и не имя; прятать убывание не нужно.
2. Складчина: несколько гостей договариваются о дорогой вещи (без денег через
   сервис). **Невидима хозяйке при любом числе участников** — в счётчике она
   одна вещь; прогресс сбора прозрачен только гостям между собой. Не собрали
   к дате — автовозврат: вещь остаётся «хочу».
3. За три дня до праздника — письмо-напоминание дарителям.
4. После праздника хозяйка на экране «что подарили» отмечает «Дошло»
   (отмечает хозяйка, а не даритель — даритель мог отправить курьером и не
   знать). Вещь → «люблю» → зал славы; имя дарителя раскрывается —
   **ровно один раз, только здесь**; предлагается связь.
5. Незабранные «хочу» остаются в комнате до следующего повода — чистить
   ничего не надо.

## 5. Комнаты и зоны

- **10 комнат-пресетов** (6 «женских»: кремовая, тёплая, изумрудная, коттедж,
  люкс, неон-bold; 4 «мужских»: лофт, геймерская, спорт, кабинет). Контракт:
  `design/package/handoff/rooms.json` — 84 зоны, прямоугольники в координатах
  430×352, кадры «открыто».
- **Пол — предустановка набора зон, а не свойство человека.** Настройка в
  профиле называется «набор зон», третье положение «Все 10» обязательно.
- Выключенная зона **исчезает вместе с мебелью** (не пустая полка).
- Спрятанная вещь не удалена: хозяйка видит, гость нет.
- Зоны: одежда, красота, украшения, парфюм, сумки, цветы, дом, впечатления,
  путешествия, книги, музыка, гаджеты, игры, спорт, обувь, часы, уход,
  «что угодно» (справочник: `handoff/zones.json`).

## 6. Экраны

**Рабочие в макете** (`design/package/Main Screen.dc.html`): телефон 430×932
со всеми комнатами и зонами (турн 15a), десктоп 1120×625 (17a), карточка
добавления (8), онбординг/гость/бронь (11–12), «что подарили» и связи (21),
кнопки (22: «полоса света» — главная, «бирка» — только «подарить» у гостя).

**Скоуп достройки** (турн 19b, приоритеты дизайна):
- **P0 — без этого продукт не работает (6):** «что подарили» → зал славы ·
  карточка вещи глазами хозяйки · карточка вещи глазами гостя · зона целиком
  списком · мои брони · письмо-напоминание за три дня.
- **P1 — ломается на второй неделе (8):** складчина изнутри · день рождения ·
  ошибки распознавания ссылки · спрятанные вещи · отмена брони · превью ссылки
  в мессенджере · пустая зона · оплата складчины.
- **P2 — после запуска (8):** спасибо дарителям · поиск · уведомления · смена
  почты и передача комнаты · удаление комнаты с чужими бронями · подсказка
  гостю · загрузка и оффлайн · партнёрские магазины.

## 7. Правила продукта (нельзя менять молча)

1. Тихая бронь всегда: счётчик — да (и он может убывать), имена и вещи — нет.
   Складчина тиха для хозяйки при любом числе участников, порога не существует;
   прозрачность сбора — только между гостями.
2. Имена дарителей раскрываются ровно один раз — на «что подарили».
3. Друзья не добавляются: ни импорта контактов, ни поиска людей, ни «возможно,
   вы знакомы». Односторонняя подписка — законное состояние.
4. Вход без пароля: почта + ссылка. СМС нет. Второй способ (Apple / Google /
   Telegram) просим один раз — перед первым шером.
5. Пол = предустановка набора зон; «Все 10» обязательно.
6. Выключенная зона исчезает с мебелью; спрятанное видит только хозяйка.
7. Пунктир = «хочу», не «нет фото».
8. Изображения комнат неприкосновенны (хотспоты привязаны к композиции кадра).

## 8. Наполнение

Карточка добавления (турн 8): **по ссылке** (автопарсинг), **по скрину/фото**
(AI-распознавание — вход уже в дизайне), **товар и услуга** (ручное; услуга =
впечатление без магазина). Вопрос «что это для тебя» — люблю/хочу.

| Канал | Статус |
|---|---|
| Ссылка (парсер) + ручное | **MVP** |
| Скрин/фото + AI → атрибуты → кандидаты каталога | архитектура сейчас, реализация Phase 2 |
| Партнёрские каталоги/фиды (и CPA-монетизация) | архитектура сейчас, реализация Phase 2–3 |
| Playwright-fallback + адаптеры магазинов | Phase 2 |
| PWA share_target (Android) | Phase 2 |
| Стриминги для зоны музыки | Phase 3 |
| Расширение MV3 · Telegram-бот | Phase 3 |

## 9. Вне скоупа MVP

three.js-вращение зала славы (в MVP — фото + CSS, как в макете; 3D только
там, где есть модель, и только для зала славы); нативные приложения;
рекомендации; соцлента; модерация сверх базовой. Оплата складчины — P1,
проведение платежей потребует решения о стране/провайдере (§12).

## 10. Нефункциональные требования

- Сцена: 60 fps, наезд камеры считается формулой (`handoff/motion.json`),
  prefers-reduced-motion уважается, цели нажатия ≥44 px, контраст ≥4.5:1
  (пол текста — .48 непрозрачности).
- Адаптив решается в коде: сцена держит пропорцию 430:352, лента чипов
  переносится, макеты фиксированы (430×932 / 1120×625) — правила растяжения
  за разработкой.
- Публичные комнаты отдаются из CDN-кэша; p95 API < 300 мс (ARCHITECTURE §9).
- Парсинг ссылки ≤4 с p95 fast path; тяжёлое — в очередь.
- Безопасность: SSRF-защита, ownership на мутациях, тихая бронь (инвариант).
- GDPR: экспорт и полное удаление. i18n: ru + каркас en.

## 11. Метрики успеха MVP

- Активация: ≥3 вещи (любого состояния) за 7 дней.
- Баланс модели: доля вещей «люблю» (здоровое ~30–50% — комната, а не витрина).
- Шаринг: комнату открыл ≥1 гость.
- Ядро: доля комнат с ≥1 тихой бронью за 30 дней.
- Замыкание цикла: доля праздников с заполненным «что подарили»; связи на
  пользователя.
- Качество парсера: доля ссылок без ручной правки.

## 12. Открытые вопросы

1. **Название и домен** (в работе: короткие кандидаты + wish.space).
2. **Монетизация**: партнёрский CPA (каталог в архитектуре) vs premium-темы.
3. **Индексация комнат**: дефолт «доступна по ссылке, вне поисковой выдачи»;
   публичный режим с OG-превью — отдельным решением.
4. **Стриминги для зоны музыки**: что подключаем первым.

## 12а. Решено

- **Рынок — РФ** (гриллинг, 2026-08-04): фикстуры парсера и порядок будущих
  адаптеров — российские магазины; Telegram — кандидат «укрепления» входа.
- **Деньги через сервис не ходят никогда** (гриллинг, 2026-08-04): складчина —
  координация договорённостей; платёжный провайдер не нужен ни в какой фазе.
- **Складчина без порога** (владелец, 2026-08-05): невидима хозяйке при любом
  числе участников (2, 5 или 12) — в счётчике «N вещей забраны» она одна вещь;
  прогресс сбора прозрачен только гостям между собой; не собрали к дате —
  автовозврат, вещь остаётся «хочу»; раскрытие имён одно на всех — экран
  «что подарили» («Скинулись пятеро», турн 21). Правило первой версии пакета
  «от пяти не спрятать» отменено автором как ошибка (магическое число без
  механизма). Счётчик хозяйки может убывать — это штатно.
- **Оживление вещи в зале славы — 2.5D-параллакс** (ADR-0001, 2026-08-04):
  платная генерация 3D и three.js отвергнуты.
