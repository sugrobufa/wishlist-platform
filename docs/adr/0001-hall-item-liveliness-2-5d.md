# ADR-0001 — Оживление вещи в зале славы: 2.5D-параллакс, платное 3D отвергнуто

Дата: 2026-08-04 · Статус: принято (решение владельца продукта)

## Контекст

Макет показывает вещь в зале славы «живой» (мягкое вращение на подиуме) и
допускал three.js «когда есть модель». Рассматривался img2threejs — агентная
генерация процедурной three.js-модели из фото. Полный оборот вещи из одного
фото без генерации невозможен физически (у фото нет задней стороны предмета).

## Решение

1. Дефолт — CSS-покачивание по партитуре макета (omSpin ±16°), уже в проде,
   бесплатно.
2. Апгрейд Phase 2 — **2.5D-параллакс по карте глубины**: monocular-depth
   открытой моделью считается один раз при загрузке фото (внутри image.ingest,
   на своём железе), подиум получает параллакс-слои с настоящей глубиной.
   Ноль стоимости за вещь.
3. **Платная генерация 3D-моделей (img2threejs, видео-обороты) — отвергнута**:
   стоимость за каждую вещь неприемлема для продукта. Пересмотр возможен
   только явным решением владельца (потребует экономику «одна модель на товар
   по canonicalUrl», не на пользователя).
4. three.js в проект не входит ни для чего. Прежняя оговорка «three.js для
   зала славы с Phase 3» снята.

## Следствия

- CLAUDE.md: запрет three.js становится безусловным.
- image.ingest в Phase 2 получает шаг depth-карты (открытая модель, оффлайн).
- Бюджет зала славы остаётся: фото + CSS/параллакс, никаких WebGL-зависимостей.
